# 开源方案评估门禁

## 何时使用

用于公众号工作流中的脚本、自动化、批量导出、文件转换、视觉检测、素材管理和跨项目安装方案。简单 bug、明确小改动、纯文案与离线排版无需执行。

## 最小检索要求

1. 先查官方文档和官方仓库，再查同类成熟项目。
2. 默认比较至少两套候选；不为凑数保留明显不适用方案。
3. 只记录公开链接与必要笔记，不大量复制源码或资产。
4. 未确认许可证前，不复制代码、模板、字体、图标或图片资产。

## 评估表

| 字段 | 必填判断 |
|---|---|
| 项目与链接 | 精确到仓库或官方文档页面 |
| 用途匹配 | 它具体解决哪一段工作流 |
| License | SPDX 或文件级许可证；未知即阻断复用 |
| 维护状态 | 最近更新、是否归档、版本与 issue 状态 |
| 安全风险 | 依赖、联网、凭证、文件写入、执行外部代码 |
| 适配成本 | Windows、Photoshop、Node/Python、中文路径与现有结构 |
| 可复用部分 | 可直接使用、需要封装或只借鉴思路 |
| 反面特征 | 应剔除的复杂度、脆弱依赖或不合适默认值 |
| 最终决策 | 复用 / 局部借鉴 / 自建，并说明原因 |

## 决策规则

- 许可证不明、项目已归档且存在高风险缺陷、要求上传敏感文件或执行不可审计二进制时，不直接复用。
- 成熟方案满足 80% 需求时，优先封装和适配，不重新实现完整轮子。
- 多套方案各有优势时，只组合边界清楚、许可兼容的部分；不要拼接成更难维护的新系统。
- 自建必须说明现成方案为何不满足，并把范围限制在最小必要功能。
- 研究结论必须能转化为依赖清单、接口、参数、测试或验收规则。
