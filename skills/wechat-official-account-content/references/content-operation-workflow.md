# 公众号端到端门禁工作流

## 原则

简单标题、局部改稿和明确小改动直接完成。多案例研究、完整文章、编辑长图、PSD/PSB 或发布切片使用分阶段门禁，防止研究、审美、脚本和质检同时失控。

```text
G0 定位 → G1 事实核验 → G2 压缩稿与语义复核 → G3 排版及成图复核 → 用户确认 → G4/G5 所需生产 → G6 分项验收 → 复盘
```

每个门禁必须有可审阅产物和明确通过记录；不自动跨过用户要求确认的阶段。

## G0 定位

确认主角、主题、目标读者、核心命题、业务目标、平台、交付格式和禁止事项，并写成一句“主旨锁定句”。同时区分账号级视觉资产与当期主题变量：当前账号默认沿用 MiSans 系列保持字体统一；配色则依据人物、品牌、材料、场地和图片重新判断。另行记录资料来源/图片说明是否公开、封面模式等项目变量。没有稳定命题时不开始大规模检索。

### G0.5 开源复用门禁（仅用于较大技术方案）

当任务包含脚本、自动化、批量生产、文件转换、视觉检测或新的交付工具时，先使用 GitHub 与官方文档比较至少两套成熟方案，再决定复用、局部借鉴或自建。每套候选必须记录：

- license 与允许的复用范围；
- 最近维护状态、版本稳定性和社区采用情况；
- 依赖、网络、文件写入和供应链安全风险；
- 与 Windows、Photoshop、公众号尺寸及现有目录结构的适配成本；
- 可直接复用的部分、必须剔除的缺陷和最终选择理由。

简单 bug、明确小改动、纯文案和离线排版任务不强制触发此门禁。不得为了“参考开源”而复制未知许可代码，也不得让调研规模大于问题本身。

## G1 案例研究

使用 `wechat-case-research`：

- 第一方与第二方来源。
- 公开事实、视觉观察、专业推断和待核实项。
- 案例分级、图片台账、署名和许可风险。
- 淘汰重复、弱证据或高版权风险案例。
- 对所有数字、日期、地点、材料、合作关系和强化词做逐项审计。
- 建立图片证据角色；人物主导文章补齐身份图，尺度装置文章补齐完整现场与细节图。

通过条件：进入正文的关键事实可追溯，图片用途与风险明确。

如果 G0.5 被触发，研究包还必须附带开源方案对比表；未完成许可证、安全和适配成本判断，不进入脚本实现。

## G2 文章终稿

1. 用 `wechat-official-account-content` 形成正文。
2. 用 `wechat-adversarial-review` 找事实、逻辑和品牌风险。
3. 用 `wechat-reader-simulation` 找流失与反感点。
4. 用 `wechat-final-editor` 合并为锁定终稿和视觉交接表。

通过条件：标题、摘要、章节、案例顺序、正文、结尾和图片角色由用户确认；同时有“原稿要点—终稿落点—处理方式”的内容覆盖清单。正文允许压缩，但不得静默遗漏。

## G3 编辑长图 / 小红书整套校样

使用 `wechat-editorial-longform`。先建立连续长图视觉系统和完整缩略校样：

- 画布宽度确定，高度随内容延展。
- 主、中、快速案例不平均铺陈。
- 图片结构、文字量、留白和章节密度有变化。
- 只输出校样，不提前批量生成 PSD 或切片。
- 校样必须展示整篇内容覆盖，不以少数精致模块替代全文；人物/工作室主导文章需在前段完成身份介绍。

小红书按 `cross-platform-distribution.md` 的内容驱动分页规则生成整套校样，无默认固定页数或区间；不以公众号连续高度规则替代逐页阅读。

通过条件：压缩文案与实际成图已核对事实限定、语义和图文对象，并由用户确认完整校样。原稿通过、视觉认可均不能代替这次复核。

## G4 代表性 Photoshop 样稿（仅用户要求 PSD/PSB 时）

使用 `wechat-photoshop-delivery`：先做字体审计，再选择一个能覆盖标题、正文、智能对象、蒙版和装饰的代表性页面。

通过条件：用户在 Photoshop 中确认文字可编辑、图片可替换、蒙版独立、图层命名和视觉一致性。

## G5 批量生产

样稿通过后才生成完整 PSD/PSB、需要的章节文件、完整预览 PNG 和语义切片。禁止覆盖现有设计文件，禁止为等高切片破坏语义边界。

## G6 分项 QA

使用 `wechat-visual-qa` 检查：

- 案例、图片、章节和文案版本完整。
- 手机端字号、重叠、越界和主体裁切。
- 文字、智能对象、蒙版、字体和图层命名。
- 切片无缝、顺序正确、与完整长图一致。
- PSD/PSB 渲染与确认版 PNG 一致。
- 指定字体真实加载，正文模块字号与行距一致。
- 已确认删除的资料、图片说明和内部证据标记没有被模板带回。
- 封面、原图、摘要等用户点名的独立交付物已真实输出并可打开。

内容核验、语义复核、视觉检查、导出一致性、用户确认和发布条件分别记录版本、证据与状态。只有本次交付所需项目通过才能声明对应完成；未做的检查不能冒称通过，不能以关键词或自评高分证明事实准确。

## 复盘与复用

发布后有实际数据才记录打开、完读、转发、收藏、咨询、读者反馈和有效案例。复盘规则先作为候选改进；经过验证并获得用户明确写入授权后才更新 Skill。一次性的项目偏好保留在项目文档，不写成全局规则。

## 确认记录与本地更新边界

- 每次确认记录对象、版本、范围与原始确认依据。视觉认可不代表事实核验完成，内容通过不代表平台发布授权。
- 先查已有确认。范围明确且未变时不重复询问，并同步与依据不符的旧状态；范围变化或确实不清楚时只询问缺失部分。
- 用户要求先审核时，必须先展示拟增补内容、涉及文件与影响，明确批准写入后再修改 Skills。一般“继续、通过”只作用于当时明确的审核对象，不能扩大为其他更新权限。
- 本地更新、Git commit、Git push、平台发布互相独立。提交前展示文件、diff 摘要、验证、分支与提交信息并等明确授权；推送前说明提交、远程与分支并另等授权。只有明确“提交并推送”才同时授权两步；工具批准不替代用户批准。
- 只完善批准范围，合并已有规则而非重建；跨会话规则使用相对引用与可迁移字段，不依赖本次聊天、临时路径或项目特例。

## 最小执行包

| 请求 | 最小 Skill 组合 |
|---|---|
| 标题或局部改稿 | `wechat-official-account-content` |
| 多案例正文 | `wechat-case-research` → 内容 → 三类文字审校 |
| 小红书逐页图文 | 跨平台分页规则 → 事实与语义复核 → `wechat-editorial-longform` 小红书分支 → `wechat-visual-qa` |
| 公众号长图 | 前述流程 → `wechat-editorial-longform` → `wechat-visual-qa` |
| 分层 PSD/PSB | 前述流程 → `wechat-photoshop-delivery` → `wechat-visual-qa` |
